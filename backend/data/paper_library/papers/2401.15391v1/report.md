## 2. 一句话总结

本文构建了一个针对多跳查询（Multi-Hop Query）的检索增强生成（RAG）基准数据集 MultiHop-RAG，并通过实验发现现有 RAG 系统在检索和回答多跳查询时表现不佳。

## 3. 研究背景

- **RAG 的兴起**：检索增强生成（RAG）通过外部知识库为大型语言模型（LLM）提供相关信息，有效缓解幻觉并提升回答质量，已广泛用于聊天机器人、金融分析等实际场景。
- **多跳查询的挑战**：真实用户经常需要从多个文档中检索并推理获得答案（如比较不同公司的财务指标），但传统基于向量相似度的检索方法难以处理这种需要跨文档聚合信息的复杂查询。
- **现有基准的不足**：已有的 RAG 基准（如 RGB、RECALL）仅评估单跳查询（答案可从单一证据中获取），缺乏专门针对多跳查询的评测数据集。

## 4. 核心问题

- **问题**：现有 RAG 系统能否有效处理多跳查询？如何系统性地评测其在多跳场景下的检索与推理能力？  
- **空白**：缺少一个包含知识库、多跳查询、正确答案及对应支持证据的标准化基准数据集。

## 5. 方法详解

### 5.1 数据集构建流程（基于 GPT-4 辅助生成）

1. **知识库构建**：采用英文新闻文章数据集作为外部知识库（RAG 的知识源）。
2. **证据抽取**：从每篇新闻中提取事实性句子作为可能的支持证据。
3. **桥接主题/实体定义**：人工或利用 GPT-4 为两个不同证据定义共享的桥接主题（bridge-topic）或桥接实体（bridge-entity），使两条证据产生关联。
4. **多跳查询生成**：将桥接主题/实体输入GPT-4，生成以下四类查询：
   - **推理查询（Inference query）**：需要从多个证据中推断关系。
   - **比较查询（Comparison query）**：比较多个数据点的异同。
   - **时间查询（Temporal query）**：对事件进行时间顺序分析。
   - **空查询（Null query）**：无法从知识库中得出答案的查询，用于检测LLM的幻觉。
5. **答案与支持证据标注**：随查询生成对应的标准答案及其依赖的多个证据。
6. **质量验证**：人工或自动检查查询、答案与证据的合理性与一致性。

### 5.2 多跳查询分类

- **推理查询**：需推断不同文档间隐含的逻辑关系。
- **比较查询**：对比不同来源的数据或观点。
- **时间查询**：涉及事件的时间顺序或趋势。
- **空查询**：无有效答案，用于测试LLM是否会产生幻觉。

### 5.3 RAG 系统实现

- 采用 LlamaIndex 构建标准 RAG 管线：文档分块 → 嵌入 → 检索 → 生成。

## 6. 关键创新点

1. **首个多跳RAG基准**：MultiHop-RAG 是第一个专门针对多跳查询的RAG评测数据集，填补了该领域的空白。
2. **四类查询设计**：系统分类多跳查询，并引入“空查询”评估幻觉控制能力。
3. **端到端构造流程**：利用 GPT-4 半自动生成高质量数据，并提供完整的支持证据，便于细粒度分析。
4. **开源与可复现**：数据集及代码均已公开，支持社区进一步改进。

## 8. 主要结果

1. **检索环节**：现有嵌入模型在检索多跳查询所需证据时表现不满意（recall偏低）；不同模型间差异较大，但整体效果不足。
2. **推理环节**：即使给定正确的多条证据，当前最强LLM（包括GPT-4）在回答多跳查询时仍然存在明显困难，尤其是比较查询和时间查询。
3. 现有RAG方法在处理多跳查询上尚未达到令人满意的水平，亟需针对性改进。

## 9. 局限性

1. **数据集规模与多样性**：仅基于新闻文章，可能无法覆盖所有领域（如医学、法律）的多跳查询。
2. **生成质量依赖GPT-4**：查询、答案和证据均由GPT-4辅助生成，可能引入模型偏差或固有错误。
3. **未考虑多跳链式推理**：数据集聚焦于需要多个证据但推理步骤较简单的查询，对更复杂的长链推理覆盖不足。
4. **实验不完整**：仅测试了检索和给定证据下的生成，未评估端到端RAG系统的整体表现（如检索+生成联合效果）。
5. **缺乏基线RAG方法**：没有与现有RAG框架（如LangChain, LlamaIndex默认流程）进行对比，仅比较了嵌入模型和LLM。

## 10. 对用户研究方向的价值

1. **基准参考**：若用户从事RAG或LLM评测研究，MultiHop-RAG可作为评估多跳场景的标准测试集。
2. **改进方向**：实验结果提示现有RAG在检索和对齐多源证据方面存在短板，可推动研究新型检索策略（如图检索、多步检索）或推理增强机制。
3. **幻觉检测**：空查询设计为评估LLM是否产生幻觉提供了关键测试用例。
4. **可扩展性**：数据构造方法可复用于其他领域（如金融、医疗）的RAG基准构建。
